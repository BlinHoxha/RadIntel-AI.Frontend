# M07 viewer acceptance plan

12 November 2026. Planning record for synthetic viewer work. Every threshold and later increment below is proposed and needs its own approval. No clinical acceptance or diagnostic use is claimed.

## Current baseline and evidence

M06C pins the official OHIF 3.11.1 artifact and serves it in an isolated loopback iframe. The parent retains credentials and sends only checked context and requested pixels through a bounded channel. The proof renders three synthetic CT slices and one synthetic DX image; its three browser cases check rendering, privacy, report text retention and disposal. They do not check tools, measurement accuracy, geometry labels, multi-series navigation or clinical scale performance. See [M06C evidence](17_M06C_Pinned_Viewer_Proof.md#final-local-validation-2-november-2026), [pin](../viewer/ohif.lock.json), [parent](../src/features/imaging/ViewerProof.tsx) and [browser tests](../e2e-viewer/viewer.spec.ts).

The present [configuration](../viewer/config.js) names no extra modes or extensions, selects only the bundled `dicomjson` source, disables study lazy loading, limits one worker, two interactive requests, one thumbnail request, zero prefetch and a 64 MiB pixel cache. The [bootstrap](../viewer/bootstrap.js) groups supported instances by series UID, assigns display ordinals from list order and supplies only present orientation, position, pixel spacing and rescale metadata. It omits demographics and acquisition date. The [synthetic generator](../viewer/synthetic.mjs) supplies 0.75 mm row/column spacing, axial direction cosines and CT positions 2 mm apart; these are fixture values, not calibration evidence. The [M06B transport contract](16_M06B_Scoped_Viewer_Transport.md#implemented-api-and-frontend-scope) is limited to unsigned, single-frame, 16-bit monochrome raw pixels. The [M06C boundaries](17_M06C_Pinned_Viewer_Proof.md#remaining-boundaries) describe unsupported formats, ordering and identity limits.

The pinned bundle contains OHIF code for common tools, but tool presence in bundled JavaScript is not evidence that this product enables or safely configures a button. The actual toolbar, mode, keyboard and layout behavior of this pinned wrapper has **not been verified**. The [OHIF 3.11 toolbar module](https://docs.ohif.org/3.11/platform/extensions/modules/toolbar/) and [viewport guide](https://docs.ohif.org/3.11/user-guide/viewer/viewport/) describe available configuration and Basic Viewer behavior; the product must test each adopted action in its own pinned wrapper.

For M07, configure only the approved buttons/tool groups in the pinned wrapper; inspect runtime behavior before claiming them enabled. Verify those blocks after every tool change. No measurement enters a report automatically.

## Layout and failure behavior

Proposed desktop layout places the scoped viewer beside the existing manual report editor, with an explicit resize or collapse control, a single viewport first and an optional two-viewport comparison within the _same authorized study_. OHIF 3.11 supports selectable viewport layouts in its [viewport guide](https://docs.ohif.org/3.11/user-guide/viewer/viewport/); whether the pinned wrapper exposes them is **not verified**. Do not show other-patient or prior-study controls. The parent order/patient identity banner remains authoritative, and each viewport must show study/series/SOP UID and slice position or a visible “position unavailable” label.

Keyboard acceptance: reach and operate open/close, series selection, scroll, tool selection, reset and report editor without a pointer; give focus back to the open control when closed; announce loading, unsupported data and failure as text. At narrow widths retain report editing policy already implemented by the product and make the viewer collapsible. On timeout, unsupported study, revoked access, network error or close, remove the child context; keep the report editor mounted and its unsaved draft unchanged. The current [parent](../src/features/imaging/ViewerProof.tsx) and [imaging panel](../src/features/imaging/ImagingPanel.tsx) provide the starting behavior, while [browser tests](../e2e-viewer/viewer.spec.ts) currently cover close and logout only.

Warnings must identify the limitation without implying that a missing image means no study exists. Image availability remains Unknown and processing NotTracked. Exact wording and clinical comprehension need owner/clinical review. For supported images, bind display/annotation to the stored study/series/SOP UIDs, not to generated ordinals. The parent identity banner and backend authorization remain authoritative. No pixels, annotations, identity or measurements are persisted by the viewer.

## Proposed performance and browser measurement

Candidate browsers are current desktop Chromium, Firefox and Edge on supported Windows hardware; owner and clinical reviewer must agree the final matrix. Candidate budgets, **proposed and needing owner agreement**, are first supported frame ≤ 5 s on a warm local synthetic run, slice switch ≤ 500 ms at p95 over 100 actions, ≤ 64 MiB configured pixel cache, ≤ 250 MiB incremental renderer/worker heap after a 100-slice bounded fixture, and no upward retained-heap trend across 20 open/close cycles. The 64 MiB cache setting is already present in [config](../viewer/config.js); it is not a total memory or GPU bound. Prior 5–14 s local observations in [M06C](17_M06C_Pinned_Viewer_Proof.md#final-local-validation-2-november-2026) make the 5 s candidate deliberately unaccepted.

Measure cold and warm runs separately on recorded browser/OS/GPU/CPU, network profile and synthetic study size. Capture performance marks at context request, frame delivery and visible render; record p50/p95, JS heap where exposed, worker count and GPU/process memory where measurable. Repeat study and open/close cycles, check concurrent requests ≤ 2 and queued requests ≤ 32, and compare retained memory to baseline after garbage collection where the browser allows it. Mark unavailable metrics explicitly rather than inferring VRAM release from iframe removal. Lazy load the viewer module/artifact only after opt-in and fetch only selected instances; the current [config](../viewer/config.js) sets `enableStudyLazyLoad: false`, so this remains an implementation and measurement target.

## Clinical gate and open decisions

Before any diagnostic claim, a named clinical reviewer must inspect source-instance identity, orientation markers, pixel spacing and measurement units against known fixtures; exercise window/level, navigation, warnings and failure recovery; confirm that report editing remains safe; and sign a dated acceptance record listing browser/hardware, fixture versions, observed results, limitations and rejected cases. Engineering test passes alone do not grant clinical acceptance. Release also depends on institutional M02 identity/hosting, privacy/security and vendor data validation.

Open for the owner and clinical reviewer:

1. Which tools and optional presets, angle or ROI have clinical value? Which actions must be unavailable?
2. Which desktop browsers/hardware, accessibility requirements and performance/memory budgets are acceptable?
3. Who is the clinical reviewer and what documented sign-off process is required?
4. Is any real de-identified data ever allowed in a later approved validation task, and under what governance?
5. Which upstream artifact, codec/font notices, license inventory and dependency security checks must be completed before distribution? See [NOTICE](../viewer/NOTICE.md) and [dependency inventory](../viewer/dependency-inventory.json).

Owner decisions, 12 November 2026: questions 1 and 2 are answered. M07 tools are the core set only — window/level, zoom, pan, slice and series navigation, and length in mm — with no presets, angle or region of interest. Supported browsers are Chrome and Edge. Questions 3–5 (budgets, clinical reviewer, data and licensing) are deferred to later increments.

## M07B implementation record (12 November 2026)

M07B adds geometry and safe navigation without any viewing tool. Implemented in the frontend only; the backend contract, OHIF artifact and hosted CI are unchanged.

- Fixtures: [synthetic generator](../viewer/synthetic.mjs) adds a `GEO` study (shuffled axial stack z 4/0/2 mm at 0.75\0.75 mm; orthogonal series with Pixel Spacing `0.5\1.0` and direction cosines `1\0\0\0\0\-1`; one image without spacing; one multiframe and one 8-bit image outside the proof profile) and a `MISMATCH` study whose second instance carries another study UID. The existing CT and DX fixtures are byte-identical. Hashes are in the [fixture manifest](../viewer/fixtures.lock.json).
- Planning: [geometry module](../src/features/imaging/geometry.ts) groups supported instances by series, orders a series by position along its slice normal only when every instance has the same valid orientation and a position, and otherwise keeps the received order with "Slice order unverified". Orientation letters come from the direction cosines (LPS: L/R, P/A, H/F). Unsupported instances are excluded with "Multiframe image unsupported" or "Unsupported image format"; a series without spacing shows "Measurement unavailable: pixel spacing missing".
- Display: the [parent](../src/features/imaging/ViewerProof.tsx) sends the child only the displayable instances in planned order and labels the image on screen from its own checked metadata: series UID, SOP instance UID, "slice n of m", position, orientation and pixel spacing. Series selection and Previous/Next slice are native, keyboard-operable controls. A context rejected by the backend (for example the identity mismatch) shows "Viewer unavailable: the image identity or format could not be verified. Manual reporting remains available."; no pixels are requested.
- Child adapter: [bootstrap](../viewer/bootstrap.js) reports the frame shown in OHIF's main stack viewport (thumbnail viewports are ignored) and performs parent-requested navigation through the pinned build's `cornerstone` and `services` globals, re-applying a request until it holds, because OHIF may reset its stack after loading. This relies on internals of OHIF 3.11.1 and must be re-verified on any upgrade.
- Unsupported transfer syntax: the metadata contract does not carry it, so the backend rejects such a frame only when pixels are requested, with HTTP 503 — the same status as an unavailable image service. A `TSYNTAX` fixture (metadata in profile, archive frame labelled JPEG Baseline `1.2.840.10008.1.2.4.50`) exercises this. Owner decision 12 November 2026 (RI-M07B review): the viewer shows "Image could not be shown: unsupported image format or image service unavailable. Manual reporting remains available." instead of the narrower docs/18 wording; an exact reason would need a backend contract change in a separate task.
- Demo mode: with the proof enabled, the CT "Abdomen & pelvis" demo case opens `GEO`, CT "Head" opens `MISMATCH` and X-ray "Left wrist" opens `TSYNTAX`; `npm run test:e2e:viewer-demo` (after `viewer:prepare`) checks them in the browser.
- Browsers: the viewer browser suites run on bundled Chromium by default; `RADINTEL_VIEWER_CHANNELS=chrome,msedge` runs it on installed Chrome and Edge. The API's per-user limit of 120 clinical requests per minute is respected in the suite by waiting out the window before the last case and between browser projects.
