Prefer a self-hosted OHIF proof with a product-owned, study-scoped data source, preserving the original package's preference and the existing authorization boundary. Do not point unmodified OHIF at the current proxy: it is not a complete standard DICOMweb root. Keep a smaller embedded Cornerstone adapter as a fallback if the scoped OHIF/authentication proof is impractical. These are recommendations to test, not installed packages, final version pins or production architecture acceptance.

M06B should first prove transport, exact identity, decoding and lifecycle cleanup on a single synthetic study. M06C then proves the pinned OHIF build against that contract. M07 follows with full tools, layout, performance and clinical acceptance. M02 remains mandatory before real-patient use. Local M05B application preparation remains separate; SQL 003 is prepared but unapplied to application databases.

## Specific compatibility and validation gaps

1. The standard viewer's study queries cannot be mapped directly to a route whose identity is a persisted RadIntel study UUID. General search/upload/store/bulk retrieval is intentionally absent. Any adapter must expose only the currently authorized linked study.
2. Metadata UID checking currently rejects a wrong StudyInstanceUID when tag 0020000D is present, but does not require that tag or enforce requested series/instance UID consistency. Strengthen the viewer manifest/metadata path with resource-specific required identifiers and exact child matching before it can generate pixel requests. Do not weaken this by relying only on archive patient verification.
3. Frame handling checks the outer multipart media type, not a complete decoding contract: boundary/part count, transfer syntax, dimensions, frame count and decoded byte expectations need explicit validation. Current Accept requests octet-stream frames; compressed/JPEG/JPEG2000 support is unproven.
4. BulkDataURI removal is deliberate protection. It also means arbitrary bulk-data lookup, overlays and advanced object types cannot be assumed. Unsupported objects must stay unavailable with a clear reason.
5. There is no viewer capability/manifest contract or complete acquisition/readiness model. Link count and successful metadata are not proof that every frame is ready. A proof manifest can describe what was validated at that request, not authoritative ingestion completeness.
6. Four concurrent imaging actions and identity verification per read can constrain latency. Use a small request queue (initial proof at most two active requests, both below the backend cap), lazy metadata and bounded cache. Measure QIDO overhead before considering any verification cache or new rate policy.
7. The current auth/client generation guard protects ordinary requests. Worker, decoder, metadata, display-set and GPU caches need cancellation and disposal on logout, institution/order/study change, authorization failure and unmount. Revocation cannot erase pixels already delivered; stop further retrieval and clear the display when detected.
8. Both the API CSP and any frontend/reverse-proxy headers must be inspected independently. A separately hosted viewer needs deliberate worker/WASM/frame policies and same-origin transport. No CDN worker, wildcard origin or credential-bearing navigation URL.

These findings identify work for the next increment; this assessment does not fix production code or claim new security coverage.

## Proposed data and authentication contract

This is a draft for M06B, not an existing endpoint or schema.

- Add a read-only POST viewer-context/manifest operation under the existing facility and imaging-order resource. Request contains the persisted studyId only, not an upstream URL or client-supplied patient/issuer/UID. The server resolves membership, order assignment, stored linkage and exact archive identity before returning anything.
- The response uses a named DTO with contract version, stored studyId, matched StudyInstanceUID, bounded series descriptors and per-series supported/unsupported status. Include required SOP identity, image dimensions/bit depth, photometric interpretation, frame count, transfer syntax and geometry only when validated from source. Do not return raw upstream retrieval URLs. Full instance metadata can be lazy and bounded rather than all loaded at once.
- Keep verified resource APIs beneath the stored study route. Pixel requests are derived only from manifest-approved series/instance/frame identifiers and reauthorized server-side. Never trust manifest data as an authorization grant. Treat context as transient, not a new persisted session table.
- Preserve recent-MFA signing and report concurrency behavior independently. Viewer inspection does not claim a case, submit, save or sign a report.
- Extend the shared authenticated request layer with a binary response mode, bounded byte reads/media-type checks, signal propagation and the same context-generation/error/expiry behavior. Never create a raw unauthenticated frame-fetch path or duplicate credentials into persistent storage.
- For an isolated OHIF build, first test a parent-owned transport bridge using a dedicated MessageChannel after exact origin/window/nonce checks. Expose only typed metadata/frame operations for the current stored study, with bounded messages and cancellation; no arbitrary fetch URLs/headers. The parent keeps product credentials, and transfers only authorized bytes to the trusted child. Child reload/context changes close the channel and dispose caches. This proposal must pass the proof before adoption; a same-origin frame is not a security isolation boundary against untrusted scripts.
- If the bridge is impractical, compare direct same-origin authenticated data-source requests under the selected M02 session design before changing architecture. Do not place product tokens, archive credentials, patient identifiers, StudyInstanceUIDs or dynamic PACS/configuration URLs in browser navigation. Keep launch context transient and viewer route generic.
- Distinguish not configured, not linked, loading, limited supported data, unsupported data, unavailable/revoked and technical failure. Keep manual reporting usable and unsaved form contents intact. A successful proof remains explicitly synthetic/non-diagnostic until acceptance.

Start with deterministic project-generated synthetic DICOM JSON and uncompressed 16-bit MONOCHROME2 multipart frames over an owned loopback HTTP fixture. Include patient issuer and exact study/series/SOP IDs, known pixel grids, multiple CT slices and an X-ray frame. Record generated fixture hashes and expected pixels; avoid patient data or public dataset rights assumptions. Follow with signed-value/rescale, MONOCHROME1, oblique/spacing and compressed/multiframe fixtures before extending claimed support. Unsupported types stay disabled. Do not raise the existing 16 MiB/60-second caps to pass a synthetic test.

Initial targets for the local proof are two concurrent reads, a 64 MiB pixel-cache ceiling and 64 MiB decoded per-instance ceiling, with fail-closed behavior beyond them. These are proposed proof budgets, not measured performance or final clinical-scale limits. Log only synthetic performance aggregates; establish actual browser/GPU/reference hardware and first-frame/interaction thresholds before M07 acceptance.
